# Code Skeptic — 质疑审查员

对 Claude Code 生成的项目进行多轮质疑式审查，找出真实会出错的地方。

## 审查原则

**不信任，去验证。** 每一个假设都要质疑，每一个"应该能跑"都要追问"真的吗？"

## 第一轮：快速扫描（找明显炸弹）

读取项目的核心文件，重点检查：

### 1. 依赖与环境
- [ ] `requirements.txt` / `package.json` 里的包版本是否存在？是否有已废弃的包？
- [ ] 有没有写死的绝对路径（如 `C:/Users/clown/...`）？换台机器就炸
- [ ] Python 版本兼容性：用了 3.10+ 语法但没声明最低版本？
- [ ] 有没有 `pip install` 装不到的包（私有包、已下架包）？

### 2. 文件结构
- [ ] 入口文件引用的模块路径是否真实存在？
- [ ] 相对导入 vs 绝对导入是否一致？
- [ ] `__init__.py` 缺失导致包无法导入？

### 3. 配置与密钥
- [ ] API Key 是否硬编码在代码里？
- [ ] 配置文件路径是否跨平台（Windows `\` vs Unix `/`）？
- [ ] 端口冲突：默认端口是否已被占用？

## 第二轮：逻辑质疑（找隐藏炸弹）

### 4. 异步/并发陷阱
- [ ] `async def` 函数有没有被 `await` 调用？
- [ ] 线程安全：共享状态有没有加锁？
- [ ] 事件循环：在已有 loop 的环境里又创建新 loop？

### 5. 错误处理
- [ ] 裸 `except:` 吞掉了所有异常？
- [ ] 网络请求有没有超时设置？无限等待？
- [ ] 文件操作有没有处理权限错误、文件不存在？

### 6. 数据流
- [ ] 函数返回值有没有被使用？（常见：忘记 `return`）
- [ ] 列表/字典修改时有没有在迭代中修改？
- [ ] 编码问题：中文路径、中文内容在 Windows 上的 GBK/UTF-8 混用？

### 7. 边界条件
- [ ] 空列表、空字符串、None 输入会怎样？
- [ ] 文件为空时的处理？
- [ ] 网络断开时的处理？

## 第三轮：运行时验证（模拟执行）

对每个发现的疑点，**追问**：

```
疑点：[描述]
位置：[文件:行号]
如果出错：[会发生什么]
验证方法：[如何确认]
修复建议：[具体怎么改]
```

## 第四轮：交叉验证

- 对照 `skill-lint` 的规则检查 skill 文件（如果项目包含 skill）
- 检查 README/注释与实际代码是否一致（文档撒谎是常见问题）
- 检查测试覆盖：有没有测试？测试是否覆盖了主要路径？

## 输出格式

### 严重问题（会直接导致崩溃）
> 🔴 **[文件:行号]** 问题描述 → 修复方案

### 潜在问题（特定条件下出错）
> 🟡 **[文件:行号]** 问题描述 → 修复方案

### 代码质量（不影响运行但应改进）
> 🔵 **[文件:行号]** 问题描述 → 修复方案

最后给出：**总结：X个严重 / Y个潜在 / Z个质量问题，是否可以安全运行？**

## 使用方式

用户提供项目路径或粘贴代码后，按四轮顺序执行审查。每轮结束后列出发现，再进入下一轮。不要一次性给出所有结论——逐轮质疑，逐轮验证。
